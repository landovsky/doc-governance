One model for every repo's docs

Every document declares — in YAML front matter — a maintenance class, a derived citeability tier, and a repo-local type. Trust is computed, never inferred by reading the body or asking who wrote it.

Why this exists — two failures we watched happen

Competing sources of truth. One repo had three hand-kept registries of "what briefs exist," silently disagreeing: 23 vs 21 vs 21 — and a note claiming one was auto-generated when it wasn't.

Decisions that never propagate. An ADR was ratified — "generate the index from front matter" — and simply never built; docs and code drifted apart with nothing flagging it. A brief handed to an outside dev described five routes when the code had two, written present-tense as fact.

The taxonomy was never the problem — the lack of enforcement was. So trust here is a front-matter computation a CI gate can check, not folklore.

Three orthogonal axes

class ⊥ tier ⊥ type. The class is the primary axis — the thing an agent acts on. Tier answers "may I cite it?" and is derived, never hand-set. Type is a semantic label, not a behaviour.

immutable

True at a point in time. Never edited — you supersede with a new doc.

date-of-record: date · raw evidence uses event_date

living

Tracks the code. You own its freshness against covers[].

requires covers + last_verified

transient

Has a status. Resolves, then steps aside to archive.

a spec also links ships

canonical — citesource — never citearchive — history

immutable no longer means one thing: an ADR (canonical — cite) and a transcript (source — never cite) share the edit rule but differ by tier. Two invariants: source ⟹ immutable, and a superseded/terminal doc always derives to archive. Curious how a doc lands in each cell? Drive it below.

The lean front-matter surface (v0.2.1)

  
v0.2.1 cut the surface to fields something consumes. Required core is three keys; the rest is
    conditional on class, derived, or gone.

  

    
# REQUIRED CORE — every doc
class   immutable | living | transient
type    repo-local label (_types.yml)
title   human title

# + ONE date-of-record, by class
immutable → date      # raw/source → event_date
living    → covers + last_verified
transient → status    # a spec also: ships

# DERIVED — never hand-set
tier     canonical | source | archive
status   on living / immutable (see playground)

# GONE in v0.2.1
updated   → read git (git log -1)
audience, granularity → dropped
owner     → default in .docgov/manifest.yml

        that's the bar. Once status is surfaced only when abnormal,
        grep -rn '^status:' is your stale / archived / superseded worklist.

    

  







  
The one rule an agent must not break

  
Everything above hangs on last_verified for the living class —
    it is what CITABLE trusts. So the model is strict about who may move it.

  

    
last_verified is a steward attestation, not a machine check.

    
A human sets it when they have re-confirmed the doc against its covers[]. An agent may run the
      check and propose a value — it never stamps today's date on its own judgment. A clean automated scan means
      "no conflict found," not "a steward vouches for this." (Symmetric to stale, set only by the sweep.)

  

  

    
adopted ≠ verified

    
When you backfill front matter onto a pre-existing doc, set last_verified to the date the content
      was last genuinely confirmed (git author-date of its last substantive edit), not today. If code moved since,
      the doc is correctly drift-stale and waits in the review queue — that is the system working. Stamping today would bless
      N unread docs as canonical in one PR: the exact competing-truth failure the model exists to prevent.

  







  
How a doc moves through its life

  
Raw evidence becomes a plan, ships, and turns into durable truth. The ★ edges are the ones real repos kept failing.

  
transcript ──▶ brief ──▶ spec ──▶ [ ships #PR ] ──▶ reference / domain-doc
(imm·source)  (transient·plan)   ★ auto-archive    ★ (living·canonical)
                     └── decision ──▶ ADR ──▶ ★ propagates into the living doc
                                     (imm·canonical)

  
Supersede, never delete. On ship a transient sets promoted_to and derives to
    archive — kept as history, dropped from the "current" view. The transcript stays
    source forever. See it in the playground: the "Shipped spec" scenario.







  
Enforcement — computed, not trusted

  
Because trust is a front-matter computation, a tool can check it. The docgov CLI runs the same
    CITABLE you drove above.

  

    

      
docgov sweep

      
# find living docs whose covers[] drifted
$ docgov sweep
DRIFT  …/spec/model.md:7  (last_verified=2026-08-20)
         └─ spec/learn.html: changed in working tree

# --write stamps status: stale (machine-set marker)
$ docgov sweep --write
$ grep -rn '^status: stale'   # your worklist

    

    

      
docgov check  (the CI gate)

      
# lint every governed doc; non-zero exit fails CI
$ docgov check
✗ …/foo.md
    - forbidden key (v0.2.1): updated  → …/foo.md:5
    - tier=source disagrees with derived canonical
    - covers[] path does not exist: app/gone.rb

    

  

  
Plus a shrink-only .doc-todo grandfather list (pre-existing messes are frozen,
    never grown), one generated index (hand-kept registries banned — remember the 23-vs-21-vs-21), and a retire-on-ship
    gate. The taxonomy is not the point — enforcement is.
