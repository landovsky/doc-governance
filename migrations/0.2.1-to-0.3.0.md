# Migration 0.2.1 → 0.3.0

Bring a repo pinned at `model_version: 0.2.1` up to `0.3.0`. All steps are **manual**; the
per-hop codemod is **DEFERRED — TODO (tooling, later)**. See
[`../guides/MIGRATING.md`](../guides/MIGRATING.md) for the surrounding workflow, and
[`../docs/decisions/0001-v0-3-0-generated-index-extension-hooks-proof-marker.md`](../docs/decisions/0001-v0-3-0-generated-index-extension-hooks-proof-marker.md)
for why this hop exists.

Unlike 0.2.1, this hop **adds capability rather than trimming fields**. No front-matter key
is removed or renamed. The one breaking change is in `.docgov/manifest.yml`, and step 1 is
not optional: until it is applied, `paths.index` does not resolve to what it says.

## What changed (the v0.2.1 → v0.3.0 deltas)

1. **One manifest spelling, and `options.index` → `options.index_mode`.** The 0.2.x parser
   matched manifest keys line-wise with no path context, so `paths.index` and
   `options.index` were the *same key* to it and the last one won. The shipped payload
   template therefore resolved its index file to the literal string `manual`. Keys are now
   unique across the whole file and the parser is nesting-aware. The long-form spellings
   (`index_file`, `types_file`, `todo_file`) and the local `index_regen` workaround still
   read, so an un-migrated manifest keeps working — but they are no longer canonical.
2. **+ `docgov index [--write|--check]`.** The index is emitted from front matter
   (`registry` + `type` + `description`) into the region between two markers, so the
   hand-written prose around it survives. `--check` fails CI when the block is stale.
3. **`registry: decide` now has defined semantics.** It was "index inclusion hint" with
   three values and no rule; a generator forced the question. `always` → always listed;
   `none` → never listed; `decide`/absent → listed iff `tier: canonical` **and** a
   non-terminal status, i.e. iff a reader may cite it today.
4. **+ Repo-local checks in `.docgov/checks/*.py`.** Under `options.tooling: pinned`, CI
   fetches the tagged upstream, so a rule added by editing `bin/docgov` never ran in CI and
   was overwritten by the next `DOCGOV_VERSION` bump. Rules placed here run inside the
   pinned gate and survive upgrades.
5. **+ The `**Proof:**` claim→evidence edge.** A backtick-quoted repo path on a
   `**Proof:**` line must resolve. Inert in a repo that never writes the marker, so this
   step is a no-op unless you adopt the convention. `**Source:**` keeps its older
   provenance meaning and is never checked.
6. **+ `docgov adr next` / `docgov adr audit`,** and a `check` **warning** (never a
   finding) when two visible branches number one decision differently.
7. **+ `.doc-todo` entries may name a single check.** A bare line still exempts the whole
   document; `path  # check:<name>` narrows the exemption, so adopting a new check does not
   silently widen an old grandfather entry into a blanket one.
8. **Folded descriptions now parse.** `description: >` followed by indented lines was
   captured as the bare fold indicator; it is now folded into one string. Nothing consumed
   `description` before the generator, so this changes no existing result.

## Steps

### 1. Rename the manifest keys (required)

In `.docgov/manifest.yml`, move to the canonical spelling and make every key unique:

```yaml
paths:
  docs_dir: docs              # unchanged
  index: MAIN.md              # was: index_file
  types: docs/_types.yml      # was: types_file
  decisions: docs/decisions   # unchanged (add it if missing — `docgov adr` needs it)
  doc_todo: .docgov/.doc-todo # was: todo_file

options:
  index_mode: auto            # was: index (or the local workaround `index_regen`)
```

Verify the rename took, rather than trusting it:

```bash
python3 -c "import importlib.util,sys;from importlib.machinery import SourceFileLoader;\
l=SourceFileLoader('d','bin/docgov');m=importlib.util.module_from_spec(importlib.util.spec_from_loader('d',l));\
l.exec_module(m);man=m.load_manifest('.');print('index ->',m.mpath(man,'index'))"
# index -> MAIN.md      (NOT 'manual')
```

### 2. Add the index markers, then generate

Put these two lines in the index file where the map belongs. Everything outside them is
yours and survives every regeneration:

```markdown
<!-- docgov:index -->
<!-- /docgov:index -->
```

Then replace the hand-kept map:

```bash
python3 bin/docgov index --write
python3 bin/docgov index --check     # must exit 0
```

**Land structural moves first.** `index --write` rewrites the map wholesale, so a directory
rename that rewrites inbound links should merge *before* you generate — otherwise the map is
generated twice and the first generation is churn in the diff.

Expect the map to grow. A hand-kept index drifts silently; the generated one lists every
`registry: always|decide` doc that qualifies, which is the point.

### 3. Audit what the `registry` rule now decides

Step 3 above turns a hint into a rule, so docs that were listed by habit may drop out (a
terminal status, or `tier: source`) and docs nobody linked will appear. Read the diff once:

- a doc that *must* stay listed although it is retired → `registry: always`
- a doc that should never be listed (internal scratch, a companion file) → `registry: none`
- everything else → leave `registry` off and let the rule decide

### 4. Move repo-local rules out of `bin/docgov`

If you patched the vendored CLI with a house rule, move it to `.docgov/checks/<name>.py`:

```python
def check(root, doc, fields):
    """Repo-local rule. Return [(message, front_matter_key | None), …]."""
    return [] if fields.get("owner") else [("house rule: owner required", "title")]
```

`fields` is the front-matter dict, and it also carries `.covers`, `.text`, `.types`,
`.manifest`, `.tier` and `.derived_status`, so a rule never re-parses a file docgov has
already read. A module may also export `sources(root, doc, fields) -> [path, …]` to add
drift anchors the sweep should watch beyond `covers[]`. Modules named `_*.py` are helpers
and are not run. A hook that raises — or fails to import — is reported and fails the gate.

Then revert the vendored `bin/docgov` to the pinned upstream copy, so the next
`DOCGOV_VERSION` bump is a clean fast-forward.

### 5. Wire the index gate into CI

In the blocking `check` job, after `docgov check`:

```yaml
      - name: docgov index --check
        run: python3 /tmp/docgov index --check
```

and in the nightly job, `docgov index --write` alongside the sweep.

### 6. Adopt `**Proof:**` (optional)

Only if you want the claim→evidence edge. Write the marker under a claim and cite the spec
that proves it as a backtick-quoted repo path:

```markdown
A task closes when its last subtask closes.

**Proof:** `spec/models/task_spec.rb`
```

A backticked value counts as a citation when it contains a `/` **and** ends in an
extension, so `#close!` and describe-block names are ignored. Be aware that this fails
*open*: `spec/models/task_spec` written without its extension is skipped rather than
flagged, so a green run is evidence about the citations it recognised, not a proof that
every citation resolves.

## Verification

- `.docgov/manifest.yml` uses `index` / `types` / `decisions` / `doc_todo` under `paths:`
  and `index_mode` under `options:`; no key name appears twice in the file.
- `docgov index --check` exits 0, and the index file still contains its hand-written prose.
- `docgov check` exits 0 (or fails only on findings you intend to fix).
- No repo-local rule remains inside `bin/docgov`; `git diff` against the pinned upstream
  copy of `payload/bin/docgov` is empty.
- `docgov adr next` prints a number higher than every ADR on every visible branch.

## Bump

Set the manifest and commit:

```yaml
# .docgov/manifest.yml
model_version: 0.3.0     # was 0.2.1
```
