# Migration 0.2.0 → 0.2.1

Bring a repo pinned at `model_version: 0.2.0` up to `0.2.1`. All steps are **manual**; the
per-hop codemod is **DEFERRED — TODO (tooling, later)**. See
[`../guides/MIGRATING.md`](../guides/MIGRATING.md) for the surrounding workflow.

This hop only **removes and derives** fields — it never asks you to add data. It is safe to apply
in bulk: the net effect is shorter, more readable front matter, with nothing new to author. The one
substantive rule (not a field move) is the `last_verified` attestation — read step 6 before you touch
any freshness date.

## What changed (the v0.2 → v0.2.1 deltas)

1. **− `updated` removed entirely.** Nothing consumed it (`CITABLE`, tier derivation, and the nightly
   sweep all ignore it); "content last changed" is read from git (`git log -1`). The temporal anchors
   git *cannot* derive — `date`, `event_date`, `last_verified` — stay.
2. **− `audience` and − `granularity` removed.** Descriptive attributes no rule consumed; `audience`
   was `both` most of the time, so it carried no signal. Filter on `type` instead.
3. **`status` is authored only on `transient`.** For `living` it **derives** to `active | stale | archived`
   (the sweep sets `stale`; a living doc whose `covers[]` all cease to exist is terminal → `archived`);
   for `immutable` it derives to `accepted | superseded` (from `superseded_by`). Write it on a
   living/immutable doc **only when non-default** — so `grep -r 'status:'` returns exactly the
   drifted/archived/superseded docs.
4. **`owner` → a manifest default + optional per-doc override.** Declare the repo steward once in
   `.docgov/manifest.yml:owner`; drop the per-doc `owner:` line unless a specific doc has a
   *different* steward. The sweep falls back to the manifest default.
5. **`last_verified` is a steward attestation** (model §5). An agent may run a check and *propose* a
   value, but never stamps today's date on its own judgment — symmetric to `stale`, which only the
   sweep sets. **This migration does NOT touch existing `last_verified` values.**

New required core: `class`, `type`, `title` + the class's date-of-record. See `CHANGELOG.md` [0.2.1]
and `spec/model.md` §12.

## Per-file manual steps (v0.2 front matter → v0.2.1)

Do these to **every governed `.md`** in the repo:

1. **Delete `updated:`** wherever it appears. Do not replace it.
2. **Delete `audience:` and `granularity:`** wherever they appear.
3. **Move `owner:` to the manifest.** Set `.docgov/manifest.yml:owner:` to the repo steward (once),
   then delete the per-doc `owner:` line from every doc — *keep* it only on a doc whose steward
   genuinely differs from the repo default.
4. **Thin `status:` on `living` and `immutable` docs:**
   - `living` with `status: active` → **delete the line** (active is the derived default). Keep an
     explicit `status:` only if it is `stale` or `archived` (a terminal/retired living doc).
   - `immutable` (non-raw) with `status: accepted` → **delete the line** (accepted is the derived default
     when `superseded_by: none`). Keep `status: superseded` on a superseded record.
   - raw / `source`-tier docs (transcript, audit, …) → **delete any `status:`** (e.g. the old
     `status: archived` the v0.2.0 transcript example carried). A source doc has no meaningful status;
     `tier: source` already blocks citation.
   - `transient` → **leave `status:` as-is.** It is still authored here (the lifecycle state machine).
5. **Leave `tier:` untouched** — its derivation is unchanged.
6. **Do NOT bump `last_verified`.** Adopting 0.2.1 is a schema change, not a re-verification. Leave
   every existing `last_verified` at its current value; a steward moves it forward only after
   re-confirming the doc against `covers[]` (model §5).

## Verify

- No `updated:`, `audience:`, or `granularity:` key remains anywhere.
- `.docgov/manifest.yml` has an `owner:`; no per-doc `owner:` remains except genuine overrides.
- No `living`/`immutable` doc carries a default `status:` (`active`/`accepted`); `transient` docs
  still carry theirs; any surviving `status:` on a living/immutable doc is `stale`/`superseded`/`archived`.
- Every `last_verified` is unchanged from its 0.2.0 value.
- Required core on every doc is `class` + `type` + `title` + its date-of-record; `tier` still matches
  its derived value.
